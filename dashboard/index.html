Why it celebrates, doesn’t rank everyone

This board shows the top contributors only — it doesn’t publish a bottom. Nobody is shamed by their position on a list. Participation in the board is opt-in, and it ranks the two things that signal real value: workflows retired (behavior change) and peers onboarded (network effect).

Token usage isn’t on it. A board that rewards volume rewards noise — and incentivizes exactly the runaway spend FinOps is trying to contain.

PMM hook

Eighty people across product, engineering, and cloud are building with AI as part of their actual work, with peer-led champions carrying adoption laterally instead of a mandate pushing it down.

Audience: internal / talent brand. (The raw 52-of-80 active figure stays internal — a denominator is for operators, not for customers.)

Activity is a leading indicator. Adoption is what people stop doing once the new way works.

How this is measured

Time-on-task is sampled, not self-reported — paired before/after timings on the same task for the same person, median of at least five executions per workflow. A workflow counts as “retired” only when the old method hasn’t been used in 30+ days, verified against actual tool logs, not a survey.

Fallback by design: every workflow keeps a non-AI path. If the model is wrong or unavailable, the work still ships. No critical task sits on a single LLM call.

What didn’t work

Stakeholder update drafting stalled — four members went back to writing them by hand, citing tone control. Cloud onboarding flattened for two weeks on a single-champion bottleneck. And the first version of the leaderboard ranked command volume, which rewarded noise; we retired that metric within a week.

“I ignored it for a month. Then Marcus showed me the runbook command on a Tuesday and I never wrote one by hand again.” — Platform engineer, month 3

PMM hook

We measure adoption by behavior change, not activity. Fourteen workflows retired this quarter across three functions — the system is replacing manual work, not adding to it.

Audience: customer-facing. The credibility line — the one that lets Deltek say “we run our own AI the way we tell customers to run theirs.”

03 / Reporting

What it’s worth.

Unit economics. Cost per active user. Hours saved per tooling dollar. The defensible numbers that turn an adoption program into a budget line.

Tooling spend · all-in
$2,400/mo

$1,600 in seats ($20 × 80) plus ~$800 variable token spend. The variable line is the one that scales with usage — it’s capped per function and watched monthly.

Hours recovered
580/mo

Across 52 active users. ~11 hours per active user, sampled not self-reported.

Cost per hour recovered
$4.14

All-in monthly cost ÷ hours recovered. The honest unit cost, with token spend included.

Capacity redeployed
3.4 FTE

580 hours/mo is roughly 3.4 full-time-equivalents of capacity returned to higher-leverage work — not headcount removed.

The honest version of “value”

Recovered hours are redeployed capacity, not banked cash. The dollar figures below express that capacity at fully-loaded rates as a proxy for what the time is worth — they are not a claim that any budget line went down. The value is real when the recovered hours go to higher-leverage work: shipping sooner, deeper customer discovery, fewer escalations. That’s the test, and it’s the question worth asking of any productivity claim, including this one.

PMM hook

We govern AI adoption with the same rigor as cloud spend — all-in cost, capacity attribution, variable-token ceilings, and an honest line between redeployed capacity and banked savings.

Audience: board / executive. The line that says this is run by someone who knows the difference between a productivity claim and a real one.

The system’s value is measured by whether decisions changed. ROI follows when the measurement does.

Reporting is a discipline, not an artifact.

Ask the operating system

Querying the program in plain language.

The dashboard is also an interface. Authorized stakeholders can ask plain-language questions of the program data and the underlying agent surfaces the answer — same governance boundaries, same audit log, same trust scaffolding. A few sample queries below.

ASK Which workflows have the most stuck adoption?
→ Stakeholder update drafting (PM) is the only workflow in yellow on the Tuesday Test. Four PMs out of twelve are still doing it manually, citing tone-control concerns. Recommended next move: a 15-minute peer session with Sarah, who’s already solved this for her own updates.
ASK Who should I onboard next for highest ROI?
→ Three engineers in the Platform team aren’t in the program yet, each ticketing into runbook generation and error log triage — both workflows with high time-on-task collapse. Estimated combined recovery: 40-50 hours/month. Sequence them after Marcus’s next onboarding session.
ASK Where’s the program off pace?
→ Cloud / Platform onboarding has flattened in the past two weeks — only one new member added vs. a trailing three-week average of two. Priya is the only active champion in that function. Worth surfacing this in the next cross-functional cadence; possibly the program needs a second cloud-side champion.
ASK What’s the unit economics on the engineering segment?
→ Engineering: $960 monthly spend, 370 hours saved, $44,400 value at $120/hr fully-loaded. Cost per hour saved: $2.59. ROI: 46x. The strongest segment economics in the program by a wide margin — reflecting both headcount and the high per-task velocity of code-adjacent workflows.
ASK What’s the next champion likely to emerge from?
→ Dev (Engineering) — currently ranked #4 on the leaderboard, but with the steepest velocity of new command authorship in the past 30 days. Has already informally onboarded two peers without being asked. Worth a direct nudge from Marcus to formalize the champion role within the next two weeks.

Demo queries shown above are pre-canned for illustration. In production, this surface routes through Claude (or the model of choice) with authorization scoped to the requester’s permissions, full audit logging, and a fallback to deterministic queries when confidence is low.
